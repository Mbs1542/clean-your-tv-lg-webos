# Theme selection, storage and transport (candidate)

Classic and Alpine are packaged in both editions. Classic is the unchanged default until an explicit choice; Alpine uses `builtin:alpine`. Channel remains an external, independently versioned showcase distribution. The historical external Alpine listing is archived; its published immutable bytes are retained.

## Trusted modules

- `theme-data.js`: public GitHub URL/collection resolution; commit pinning; bounded sequential XHR; SHA-256; typed manifest/rule validation; image signature/header/dimension checks and native image decode; Blob handle cleanup.
- `theme-store.js`: app-origin IndexedDB `ctv-themes-v1`, object store `packages`, keyed by descriptor digest. Writes are complete transactions. It bounds installed payload bytes at 24 MiB and eight cached versions, additionally subject to the device's own quota. Download failures do not commit partial packages.
- `theme-manager.js`: `tvhome.theme.choice.v1` accepted pointer plus `tvhome.theme.trial.v1` durable preview/startup marker. `selectInstalled(item)` verifies builtin/cache membership through `list()`, then applies and immediately persists without scheduling a timer. It keeps the durable marker before native preparation and CSS application, and restores the previous choice if preparation or persistence fails. Only showcase `begin(item)` schedules the 20-second trial: Keep commits the accepted pointer; Back/Revert/timeout restores the previously accepted appearance. LAN and URL installation choices use immediate installed selection. Incomplete trial/startup on relaunch falls back to Classic without erasing downloaded packages. Binary assets never enter localStorage.
- `theme-panel.js/css`: standard on-TV Themes settings, remote focus/navigation, URL input, explicit collection choice, installation progress/error, version selection/removal and clear-cache recovery. The trial confirmation stays outside the themed surface and leaves the app ribbon visible. Parent Settings are hidden only during the trial and restored afterwards.
- `theme-locales.js`: twelve-language settings labels. Validation/network diagnostics may use English technical messages.
- `builtin-theme-files.json`: explicit Alpine file inventory, mirrored by packaging/preview allowlists. `builtin-themes.json` pins the bundled descriptor digest. Alpine bytes and notices come from the immutable toolkit source/distribution recorded in the initial catalog review; the trusted built-in descriptor has a separate identity.

No new Luna service permissions, updater source allowlist changes, root commands, repository scripts or external CSS execution are involved. Existing emergency Home release, key-up delivery and Home routing remain independent.

## Source behavior

Accept a public `https://github.com/OWNER/REPO` or an exact `https://raw.githubusercontent.com/OWNER/REPO/FULL_COMMIT/.../cytv-theme.json` (or `cytv-themes.json`). A repository URL resolves HEAD through the GitHub commits API, then probes the root collection; a genuine 404 falls back to a root single-theme descriptor. An invalid collection does not fall back. Collection selection is explicit and binds the entry ID/version/digest. Subsequent manifest-relative files stay under the same pinned distribution directory. Credentials, queries, arbitrary hosts, moving raw URLs and traversal are rejected. Redirects are rejected when the browser exposes the final response URL. GitHub rate limits and TLS/CORS failures surface as errors without changing the accepted theme.

Descriptors are at most 64 KiB; rules 128 KiB; image assets at most 2 MiB/1920×1080 each, previews 300 KiB/960×540, total assets 6 MiB. Every named rule/image/license/credits file must match size and SHA-256. Package transfer is sequential with 15-second per-request timeout and a 60-second package deadline. Native decode must complete within eight seconds/image, after bounded header inspection. Unreferenced cached files, unsupported APIs/layout scales, malformed images and incompatible minimum Home versions are rejected. Prepared handles are released on cancellation/rejection/replacement.

Installed versions do not follow a branch or contact the author on startup. To update, install the newer descriptor and select its installed version (or trial/confirm through showcase), then remove the old inactive version. Removing an active version requires switching first. Clear downloaded themes restores Classic and empties only the theme cache.

## Profiles and updates

Theme state is separate from legacy `HomeData`/Root profile and updater contracts. Ordinary app-origin storage survives a normal relaunch; browser tests cover that path. Existing profile backup/export does not include the binary theme library. An authoritative profile restore clears the accepted pointer/trial and starts Classic, while leaving downloaded versions available for reselection. Package/application removal may clear its app-origin data. No independent profile/OTA schema is silently extended.

## Verification and remaining hardware gate

`tests/themes/transport.cjs` checks SHA-256/UTF-8 vectors, URL boundaries and real Channel payload integrity. `tests/themes/selection-ui.cjs` runs both real renderer editions against app-owned IndexedDB and simulated pinned transport: built-ins, external installation, user columns, offline reload, cancellation, timeout, interrupted trial, bad hash rejection, storage ceiling and removal. Existing isolation/geometry/legacy-input suites remain required. Package and compatibility tests must include the new files in both editions.

Browser verification does not establish TV-origin IndexedDB availability/quota/persistence, platform TLS/CORS, actual remote/IME input, standby/cold boot, updater rollback or device compatibility. Before public release record device model, firmware/webOS, remote, edition, exact package versions, installation platform, actual expected/observed results and untested cases. No device was changed or verified by the browser tests. The maintainer authorized integrating the current implementation, including Themes, Columns and categorized settings, into the unfrozen `release/next` candidate on 2026-10-29. Further refinement and hardware acceptance remain separate follow-up work.

## LAN development transport and TV catalogue (next candidate)

`ThemeData.lanSource` accepts only canonical RFC1918 IPv4 and a six-digit PIN. The separate `loadLan` route fetches `http://ADDRESS:8879/PIN/package.json`; ordinary GitHub URL installation remains HTTPS-only. LAN requests require HTTP 200 and reject exposed redirect destinations. Responses are bounded at 10 MiB (base64 overhead), decoded against declared individual limits, and passed through the same descriptor/rules/hash/image/API/minimum-version checks and native decoding before the atomic cache write. The cache contains neither LAN URL nor PIN. `tvhome.theme.computer.v1` remembers only the successful computer address; it is not a theme choice or a credential and is not added to legacy profile exports.

The toolkit serves one compiled in-memory snapshot per explicit sharing session, with a cryptographically generated six-digit PIN, fixed TCP port 8879, ten-minute expiry and a global failed-path limit. Both socket addresses and Host must identify local/private endpoints. File/null origins support packaged Home; ordinary web origins cannot retrieve packages. This is trusted-LAN HTTP, not encrypted pairing or a substitute for the existing HTTPS repository path. The TV opens no listening socket. No app privilege or updater trust changes are required. Physical-device HTTP/origin/firewall and native IME acceptance remains untested.

`node scripts/build-tv-theme-catalog.cjs` derives `launcher/theme-catalog.json` and local preview/notice files from the reviewed showcase registry. `--check` fails on drift, missing or orphaned assets; `npm run test:themes` includes that gate. Classic/Alpine are builtin cards; active Channel keeps its source URL, identity and digest. Removed/unavailable records are excluded. Packaging consumes the existing explicit inventory. Each explicit `ThemeManager.catalog(signal, onLocal)` call refreshes from `https://api.github.com/repos/Razdva122/clean-your-tv-lg-webos/commits/HEAD`, then requests `launcher/theme-catalog.json` at that exact commit on raw.githubusercontent.com. The optional callback receives validated bundled entries immediately before remote requests; callback failures reject. Only reviewed external entries are taken from that snapshot; running-version builtins remain local. Preview paths become pinned URLs within that project commit. Invalid, missing or unreachable remote data falls back to the bundled snapshot with an array `.notice`; cancellation rejects instead of falling back. Requests use existing status/redirect/size limits and nothing is persisted or installed by refresh. External IDs must match their commit-pinned source repository; installer verification still checks distribution hashes. New submissions require regenerating/reviewing catalogue assets and a normal merge into the main repository; an unmerged candidate may use fallback until those files are available there. Opening the separate showcase or Refresh invokes this without a Home update or page reload. Physical-TV network acceptance remains pending.

`tests/themes/lan.cjs` covers address/PIN boundaries, byte integrity, envelope bounds, HTTP statuses, redirects and cancellation. `tests/themes/discovery-ui.cjs` covers catalogue arrow/Tab navigation, local preview images, external download before trial, invalid addresses, retry after rejected PIN, no persisted PIN, local import and startup in both editions. These browser tests use synthetic transport and do not establish hardware acceptance. Toolkit tests separately cover the actual local HTTP server and immutable compiled snapshots.

Acceptance on 2026-10-29: `scripts/test.sh tv preview`, full both-edition theme browser suite, legacy UI and Chromium 38 compatibility passed. The toolkit suite passed 29 tests without skips against candidate export base `c2465f6329f535f075b0ab2ef6bc0d742a2588dd` (dirty snapshot). Real Chrome file-origin XHR accepted a compiled package through loopback with no mocked transport or disabled web security. Private-interface self-connections were unavailable in the development environment, so full LAN routing remains unverified. In-app browser catalogue download of the actual pinned Channel package also succeeded without changing the accepted theme. [Catalogue capture](theme-tv-review/catalog-lan.png) and [provenance](theme-tv-review/lan-catalog-provenance.json) record synthetic UI evidence, not physical-TV acceptance.


Installed-theme cards use `ThemeManager.preview(item)` to load the exact cached digest, verify its manifest/files and identity, and expose only its preview asset through a MIME-typed Blob URL. The UI owns an idempotent lease and revokes it on redraw, navigation, close, stale completion or image failure. These URLs are never persisted. Built-in previews use bundled files; the independent published showcase does not include personal installations. `installed-previews.cjs` verifies actual preview bytes and rejection of tampering; `installed-previews-ui.cjs` covers a custom theme absent from the catalogue offline in both editions and exercises lifecycle cleanup.

Root package versions and the shared renderer version are independent. Root
preparation embeds `CYTV_THEME_RENDERER_VERSION` from the shared launcher manifest;
ThemeManager uses it for theme minimum-version checks while Root's own app/update
version remains unchanged. No-root uses its normal app manifest version. The
CSS-only Itachi browser regression reads actual staged app metadata instead of
forcing both editions to the No-root version.
